# Real farm map as the face of the simulation

Goal (team request): the Simulation view shows the farm itself, drawn from an aerial photo by the team's farm map converter (`../farmmap/stylize_farm.py`, flat colours, striped fields, round trees, roads), and the simulation (crops, stages, weather effects, the week-by-week playback) is painted on that map's real fields, in the converter's illustrated style. The current hand-drawn four-field layout stays only as the fallback when no map is available.

## Data
- `src/farmmaps.js` (generated by `tools/build_farmmaps.py`, loaded right after `sites.js`): `FS.data.farmMaps[siteId] = { site, name, lat, lon, widthKm, source: 'usgs'|'s2', credit, sharpness, img: 'data:image/jpeg;base64,...' (1000x1000), fields: [{ id: 'north'|'creek'|'west'|'south', poly: [[x, y], ...] (0-1 of the map, y down), acres (measured on the photo), cx, cy (0-1), theta (row direction, radians, the converter's stripe angle) }] }` for all 14 county points. A county point's map is the example farm for that county.
- Live (server only): `GET /api/farmmap?lat&lon` now also returns `fields` (same shape, may be null) and `widthKm`, next to `map` (image URL, relative to the server origin), `photo`, `source`, `credit`, `detail`. An uploaded photo (`POST /api/farmmap/upload`) returns fields with `acres: null`.

## Which map is shown
1. A farmer who gave their own point (address or location; `FS.farmSetup.setup.point`, not the example farm) and the page is served by the server: request `/api/farmmap` for that point automatically after setup (it takes 20-40 s the first time, then it is cached), show the county map meanwhile with a small quiet note ("Drawing your farm's own map from aerial photos…"), then switch to the live map when it arrives with fields. On failure keep the county map and say so in one quiet line.
2. Otherwise: `FS.data.farmMaps[current site id]`.
3. No map (missing data, or the image fails to load): the existing hand-drawn layout, unchanged.
When the farm changes (setFarm, Change in the questionnaire), pick again.

## Drawing (src/fieldview.js)
- The map is square: fit it ("contain") in the stage, centred, panel colour around it. Draw the map image once per layout into an offscreen canvas; per frame draw only the four fields and the effects.
- Each simulator field (by id) is painted inside its real polygon each frame, in the converter's style: a slightly inset fill with soft rounded edges and the converter's field-gap colour around it, stripes along `theta` (period about map width / 56, two tones, like `render()` in stylize_farm.py), colours from the converter's palette (`PAL` in stylize_farm.py: soil, dry, grass, crop_green, crop_dark, crop_yellow, ...; copy the values you need).
- Crop and stage to style (use the week state fieldview already computes, `stateOf(fid)`): bare or no crop: soil; residue: dry; planted: soil with faint green rows; emerged to vegetative: soil blending into crop_green with `green`; flowering: crop_dark; grain fill: corn crop_dark to crop_yellow, soybean crop_green to a yellow-green; mature: corn crop_yellow, soybean and oats a golden tan; harvested: dry (stubble, faint stripes); cover crop (rye): grass green, paler while dormant in winter.
- Effects, subtle and in the same flat style: waterlogged: blue tint and a few glossy patches; dry soil (low `soilWater`): duller, yellow-brown; frost: white speckle; heat: warm tint. Keep the existing whole-map weather effects (rain, frost) on top.
- Selected field: Raw Umber outline (3 px). Hover: lighter outline. Click selects (hit-test the real polygon). Labels: the existing pill labels at each polygon's label point. Tooltip: as now, plus "Map outline about N acres" when `acres` is known.
- Caption (bottom right, as now): for a county map "Example farm near <county>, drawn from <USDA aerial photos | Sentinel-2 satellite images> · fields found automatically · weather and soils are real"; for the farmer's own map "Your farm from above, drawn from ..."; always include the source credit (`credit`), shortened if needed, in the tooltip or caption.
- The field list (legend) keeps the farm's acres from the questionnaire (the model uses those); the map's measured acres only appear in the tooltip.
- Respect reduced motion; keep 60 fps on a laptop; no horizontal overflow on a phone.

## Honesty
The map is a drawing by image processing; the four fields are found automatically and may not match the farmer's real field lines. Say so once, plainly, in the caption or tooltip ("fields found automatically; the simulation uses your answers for size and crops").

## Map quality check (added after review)
The county maps are built with `farm_fields.py --strict`: the photo must show at least three real field blocks separated by roads or field edges. Where the county point is a town or one unbroken block (Champaign IL, Saline MO, Christian KY, Lenawee MI at the last build), `tools/build_farmmaps.py` moves the 1.6 km square about 2.2 km north, south, east or west and tries again; `offsetKm` in `src/farmmaps.js` records the move. The captions say "Example farm near <county>", which stays true. Map acres are only shown in the tooltip and never used by the model.
